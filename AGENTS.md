# ImmersionCaption development instructions

## Product and privacy

- Build multilingual native macOS captions for system/application audio. User chooses the spoken language. Translation is removed; do not reintroduce it without an explicit request.
- Capture output using Core Audio process taps and NSAudioCaptureUsageDescription. No ScreenCaptureKit, screen recording requests, or microphone input. Keep tap/aggregate private, playback unmuted, and default devices unchanged.
- Require on-device recognition, with no silent cloud fallback. Discover locales/capabilities, show only on-device options in language menus, resolve saved selection within that filtered list, and recheck availability on start. Never log audio/transcripts. History is memory-only until explicit export.

## Architecture and policy

- Swift 5.9+, macOS 14.2+. Use MainActor session/presentation and structured concurrency. Domain policy and pure overlay geometry live in Packages/CaptionCore; application ports/coordinator in Application; adapters in Infrastructure; views in Presentation. Select concrete providers in AppContainer.
- Recognition uses SpeechRecognizing with an explicit locale and cumulative text/request ID/actual finality events. No Apple recognition types in domain models. Caption holds a request snapshot and language metadata.
- Show partial text immediately. Replace revisions under the same identity/time; do not append duplicate partials or wait for punctuation/isFinal. Finality marks an existing entry, never gates first display. Empty partial revisions retract; final entries are immutable.
- Keep history bounded to 300 request snapshots and rolling display to three current-run blocks. Keep the persisted maximum visible caption-line choice One/Two/Three (default Three) separate from the three-request buffer capacity. Use shared CaptionTextMetrics for TextKit line fragments, viewport height, and panel sizing; limit visible wrapped lines without truncating source/history. Let layout wrap/scroll at the selected font; do not reintroduce source cuts or automatic font shrinking. Follow live can be paused for review.
- Language changes require paused/stopped state. Snapshot selection at start; preserve previous-language history while clearing the live display on restart. No automatic language detection is implemented.
- Invalidate session/request generations on stop/pause/failure. Do not publish obsolete callbacks or visibility tasks. Never fabricate finality during maintenance rotation. There is no overlap audio buffer or cross-request deduplication; document limitations honestly.
- Hide the entire overlay after about one second of quiet PCM, using a passive per-run AudioActivityMonitoring adapter and one bounded polling task. Late recognition updates may update history but cannot reopen a silent overlay. Resumed sound alone must not show stale text. Never use visibility detection to finalize/restart recognition; it is not VAD or Apple's private algorithm. No Keep Onscreen preference remains. Unlocked positioning is an explicit, temporary editing exception: keep the panel visible without changing recognition or persisted click-through.
- Locked click-through mode hides header/Follow live controls and scrollbars and always follows new text. Interactive mode retains review controls. Preview must not override automatic hiding while running. Preserve main-window history/export.
- Overlay positioning starts locked on each launch. Unlock temporarily accepts input and exposes a dedicated native drag handle. Persist validated display-relative top-left anchors and display UUIDs; presets clear custom placement. Never reapply positioning on every caption update. Keep frames reachable on display changes. The interactive child lock panel must be reattached after orderOut and hidden with its parent; it is the only clickable region in locked click-through mode. No Accessibility permission/global mouse monitor is needed.
- Prefer focused types, explicit injection, and documented ownership. Copy HAL buffers before return, synchronize delivery/stop, and clean up partial startup. Defer overlay hosting-view creation until view startup.
- Keep icon source/provenance and native-size packaging before signing. Do not add dependencies without a concrete need.

## Verification and delivery

- Runtime changes: swift test --package-path Packages/CaptionCore, swift test, scripts/build-app.sh. Lightweight domain checks: scripts/test-core-compat.sh.
- Startup/overlay changes: scripts/check-app-launch.sh checks process/window metadata and leaves the app open. It does not test audio/permissions.
- Test custom-position migration/persistence, geometry bounds, native child-panel attachment, lock interaction/visibility, whole-line multilingual layout/following and saved line limits, locale selection/persistence, local-only failure paths, revisions, identity/finality, empty/Unicode text, bounds, passive PCM activity, silence/reappearance, and lifecycle races. Manually verify scrolling, language quality, permissions/assets, continuous audio, device changes, and Spaces/fullscreen before release.
- Maintain README.md and README.zh-CN.md together, with reciprocal language links and matching features, requirements, usage, and limitations. Maintain ARCHITECTURE.md, docs/CAPTION_POLICY.md, docs/LIVE_CAPTIONS_RESEARCH.md, docs/VALIDATION.md, and editable/rendered diagrams. Distinguish documented Apple behavior from our design choices, and automated evidence from interactive acceptance.
- Packaging: scripts/package-app.sh builds .pkg/.dmg plus checksums from the signed app. Derive version/architecture/minimum OS from the bundle. Fix .pkg payload at /Applications/ImmersionCaption.app, disable relocation, and include no installation scripts or personal data. Verify extracted payload, signature, Installer requirements, disk-image contents, and checksums; do not claim full installation testing unless performed. Keep unsigned/ad-hoc/notarization limits explicit.
- Use Git; preserve user work. Do not commit bundles/models/logs/personal history. Do not delete external apps/models when removing an integration. Embedded alternative speech engines, asset management, distribution signing, and notarization remain planned.

## GitHub Releases

- Read [docs/RELEASING.md](docs/RELEASING.md) before publishing. It records the actual CLI/device-login workflow, commands, verification, recovery, and documentation updates. This repository uses AGENTS.md; do not create a competing Agent.md.
- Reuse explicit release authorization from the current conversation; do not ask again at the final publish step. A request to build local packages alone does not authorize a new release. Complete reviewable artifacts and notes before requesting any missing authorization.
- Inspect the actual origin, release/tag state, and repository permissions. Current repository: mattt-s/ImmersionCaption. Match the bundle version/build/actual architecture to a clean, committed, remotely available source SHA. Bump version/build as appropriate for changed binaries; documentation-only changes do not require new packages. Never overwrite an existing published version or move its tag.
- Prefer release-capable connected tools when available. The connector used for v0.7.1 lacked release/asset writes, so use official gh as fallback. Locate an installed CLI first; /tmp/immersion-release-tools/gh was a verified temporary copy, not a durable dependency. Obtain missing CLI tools from official sources and verify checksums. Keep TLS checks enabled.
- SSH Git access is separate from Release API authentication. Reuse valid gh auth; only if missing/expired use `gh auth login --hostname github.com --git-protocol ssh --web --skip-ssh-key`. The one-time code comes from the Mac terminal, not a phone notification. The user completes github.com/login/device authorization; do not generate/upload new SSH keys, request chat passwords/tokens, record device codes, or expose credentials. Check credential storage rather than claiming keyring use without evidence.
- Run scripts/package-app.sh and verify the native installers. Upload only the exact versioned .pkg/.dmg/.sha256 artifacts, with bilingual notes stating actual features, requirements, signing/notarization, and test limits. Use --notes-file and a full source SHA with --target; create a draft first.
- Verify the draft target and exact three assets: uploaded state, size, and server SHA-256 digest must match local files, including the checksum file. If digests are unavailable, download and compare. Inspect/recover a partially uploaded draft; do not blindly recreate, clobber, or delete releases/assets.
- After verification, publish the authorized draft; mark normal latest versions as Latest and keep prereleases separate. Confirm published state, tag commit, expected Latest state, and actual downloads. Compare all three downloaded files with originals and run the downloaded checksum manifest. Public releases also need anonymous download checks; private releases retain their access restrictions.
- Update both READMEs with working release/asset links and docs/VALIDATION.md with actual evidence, then commit/push documentation. Do not claim signature integrity is Gatekeeper approval, or download verification is installation testing. Do not rebuild/replace published attachments merely to include later documentation commits.
